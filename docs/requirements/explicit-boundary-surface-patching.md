# 明确边界与分块补面的语义创作需求

- 日期：2026-09-03。
- 状态：需求提案；用户已授权调研和文档编写，尚未批准本提案的接口设计与实现。
- 审计基线：`8149533` / 0.17.2 / Blender 4.2.23 LTS / protocol 1 / transactions 13。
- 目标：让 Agent 像人工建模一样表达“这些点相连、沿这四条边补面、再塑形”，而非反复依赖自动边界猜测。
- 本文不宣布发布新版本，不改变 0.18 Shape Keys → 0.19 骨架创作 → 0.20 Modifier 最终化的已批准主线。

## 1. 用户问题与成功标准

用户在角色额头补面任务中发现：视觉上明确的缺口经过多次合点、细分后，
`grid_fill` 仍返回 `Grid fill created no faces`，而工具不能解释哪条边界不合适。
人工操作者可以直接指定几对连接、逐面建立侧带、调整 Grid Fill 的角点与跨度；
Agent 当前能调用若干拓扑算法，却不能充分表达这些决定。

需求不是“让任意输入强行生成面”，也不是新增一个角色专用自动补头工具。
需要补齐从意图到可检查几何操作的控制粒度，并把失败变成可采取行动的诊断。

成功必须区分三层：

1. **拓扑完成**：指定缺口被连接，没有意外重复面、交叉连接或未处理边界。
2. **几何完成**：补片符合用户要求的曲率、轮廓与边界连续性，而不只是封上一个平盖。
3. **交付完成**：需要的材质、UV、权重、绑定和保存后重载得到验证。

三层分别报告，不能把生成了面或得到一张漂亮图片直接等同于角色任务完成。

## 2. 事实、推断与证据边界

### 2.1 当前实现核对

- `mesh_topology_ops._operate` 的 Grid Fill 预检允许一个闭环，也允许两个度数为 1/2 的分量；后者包含两个闭环。
- 预检后直接调用 `bmesh.ops.grid_fill`，没有单闭环到两开链的准备阶段。
- Blender 4.2.23 底层要求恰好两条开链；界面 Grid Fill 对单闭环的支持依赖额外准备步骤。
- 底层侧轨搜索遍历未隐藏的 wire/boundary 边，不是发现顶点边界度数大于 2 就拒绝。
- 底层先尝试一组端点配对，找不到路径时才尝试另一组；找到路径后发现两侧轨重叠，会取消而不是再试另一配对。
- 当前封装把空输出统一转成 `MESH_BOUNDARY_INVALID: Grid fill created no faces`，没有明确报告上述失败类别。
- `bridge` 当前只接受两个闭合边界环；不等同于 Blender 原生界面的全部开链桥接能力。
- 当前没有直接表达“按指定循环顺序，用已有三个或四个顶点建立一个面”的公共 Mesh 操作。

## 3. 使用场景

- U01：面对失败的缺口，先得到哪些链、哪些角点和哪些候选侧轨，而不是盲目修改模型再试。
- U02：对已有明确边界，指定四边和方向，生成可预期的网格，不受周围无关边界捷径干扰。
- U03：对复杂接头，先用已有顶点创建少量连接边、三角面或四边面，建立有宽度的侧带，再填内部。
- U04：对两个开链桥接，明确端点对应、分段和方向，发现扭转后可调整，而非被闭环专用接口阻挡。
- U05：补面后沿当前参考曲面塑形，保留已确认边界，验证接缝、交叉、属性和真实绑定效果。
- U06：用户在 Agent 工作期间旋转、缩放、选择；原生保存接受当时状态，后续 Agent 不再回滚或重复保存。

## 4. 优先级与功能需求

P0 为已暴露的正确性与诊断缺口；P1 为完成手工式分块建模所需控制能力；
P2 为组合与效率增强。优先级是建议，不表示已批准版本安排。

### R01 / P0：边界检查与可定位诊断

只读检查必须区分**选中子图**和**可参与路径搜索的周围图**，返回：

- 选中分量数量、开链/闭环/分叉分类、端点、有序顶点/边引用；
- 选中度数与周围 wire/boundary 度数分别报告，不混为一谈；
- 隐藏边、内部边、非流形边、点接触及不连通位置；
- 两组端点配对各自的可达性、候选侧轨、重叠点/边和歧义；
- 封闭环的候选角点/方向、需要调用方指定的未决信息；
- 已检查范围、截断、搜索预算和未检查项。

所有引用绑定当前 Object/Mesh identity、revision、fingerprint，不依赖 Blender 真实选择。
大网格不得枚举所有简单路径：使用有界搜索，超预算报告“未知/需要明确侧轨”，不能谎称无路径。
检查不能写场景数据或推进 generation。默认不申请长寿命资源；若复用检查 token，后续写入仍须验证实时证据。

### R02 / P0：Grid Fill 契约一致性

- 两开链、单闭环、双闭环、开闭混合必须有明确、可测试的支持状态。
- 对继续承诺支持的单闭环，提供真正的角点/跨度准备；在能力未实现前明确拒绝并说明原因，不能“通过预检后必然空输出”。
- 不把 Blender 原生能力全部写成 MCP 已有能力，也不盲目把双闭环送入不支持它的 Grid Fill。
- 自动侧轨必须经过有效性检查。当前自动配对失败时，可尝试其他合格配对或报告歧义；不得选择已知重叠路径后只报零面。
- 不根据顶点度数大于 2 一刀切拒绝（E02）。
- 不得靠永久修改用户隐藏、选择或模式来使输入暂时“合法”。

### R03 / P0：错误信息可以驱动下一步

执行期错误应保留稳定外层错误码，并附结构化 `reason` 与证据，至少区分：

- 输入分量/闭环类型不支持；
- 所选边不是可用边界；
- 侧轨缺失、隐藏或被过滤；
- 两侧轨重叠，或多个候选无法明确消歧；
- 角点、方向、分段不兼容；
- 生成后质量检查未通过；
- 预算/deadline、证据漂移与恢复失败。

返回相关端点/边证据、失败阶段、是否写回、generation、恢复状态和可选下一步。
诊断不自动修改输入。MCP 人类可读错误与结构化信息保持一致；调用方遇到框架/传输纯文本错误时应保留原文，不能用二次 JSON 解析错误覆盖它。
具体 reason/error-code 名称在实现设计中冻结，本需求不擅自更换既有协议。

### R04 / P1：明确四边与配对的网格补片

调用方可以用精确 EDGE SelectionSet 加端点/有序路径证据，指定上下边、左右侧轨及方向。
无序 SelectionSet 本身不能冒充有序链；路径顺序必须检查邻接、唯一性与当前 revision。

- 四条路径除约定的相邻角点外不得相交；必须在同一 Mesh 上形成明确补片边界。
- 指定侧轨后，外部无关路径不得改变结果；不允许偷偷退回自动搜索。
- 允许明确角点/Span/Offset 等等价语义，但不得依赖当前活动顶点。
- 分段不足时，明确选择拒绝或按受控方案重采样。不能无声细分固定边界。
- 返回最终使用的四边、角点、方向、分段、内点数、面数与全部新增组件。
- 单闭环可先确定四角再拆成四边，复用同一补片内核；不是另一套不一致的写入器。

### R05 / P1：已有顶点的精确连接与逐面建模

提供封闭语义，而不是任意顶点/面数组或任意 BMesh 调用：

- 用两个精确已有顶点建立连接边；已有相同边时明确 no-op，不建立重复边。
- 按显式循环顺序，用三个或四个不同的已有顶点建立一个面。
- 检查重复面、零长/重复点、零面积、蝴蝶结自交、不可接受的重叠与非流形结果。
- 合理非平面四边形不是自动等价于无效；报告非平面性及实际三角化/法线质量。
- 新边不得隐式穿过已有面并伪装完成切割。需要分割既有面的情况应拒绝或转交明确的后续能力。
- 不隐式焊接近邻点，不隐式删除已有面，不从当前 Blender 选择猜顺序。
- 新面的材质槽、smooth、UV/权重策略显式可检查；一个调用失败不得留下半条边或半个面。

此能力用于少量有意图的连接和侧带，不是本版本引入 Knife、任意 Edge Net 或通用重拓扑的借口。

### R06 / P1：开链桥接

保持既有双闭环 bridge 请求兼容，新增对两条互不相交开链的明确支持：

- 调用方指定端点对应、方向和中间分段；
- 数量不等时明确受控重采样策略，否则在写入前拒绝；
- 不通过猜测 active edge、调用顺序或坐标近邻决定扭转；
- 报告生成的端部边界，不将开链桥接误报为整个缺口已封闭；
- 与 Grid Fill 区别：Bridge 在两链之间生成连接，Grid Fill 受四边约束；不能默认桥接已复用已有侧轨。

### R07 / P1：分块补面与塑形分离

允许先创建两侧少量连接带，再对中央区域 grid fill 或桥接。
通过现有 ComponentMap/SelectionSet 精确定位后续边界，不猜新索引。
补面只产生连接结构；后续曲率使用现有 project/shrinkwrap/relax/smooth 工具。

- 固定边界与可移动内部明确区分；可设置过渡带权重与最大位移。
- 对参考曲面使用精确 SurfaceRef，未命中不得向错误表面无限投射。
- 参考对象缺少该区域时，使用用户选择的模板/形体先验，不声称恢复不存在的原始数据。
- 不强制全四边面；三角/四边的选择由下游平滑、变形和交付目标决定。

### R08 / P1：组件血缘与属性结果

- 复用 snapshot、ComponentMap 与 exact writeback；旧顶点/边保持准确 SURVIVED 关系，新内点/边/面用明确 CREATED 或已证明的 lineage。
- 不把空间近邻或相邻旧面冒充同 domain 的精确来源。属性插值来源与组件血缘分别报告。
- 对每个新面/角点说明材质槽、UV 层完整性、插值来源及回退策略。
- 权重检查有限值、范围、锁定 Group 和影响数；未赋权/未映射如被允许，必须作为未完成交付问题显式报告。
- 复用既有 PRESERVE_INTERPOLATE / ERROR_IF_PRESENT / DISCARD 策略；无法证明请求的保留结果时恢复本次调用。
- Shape-Key Mesh 的拓扑限制保持不变，必要时先 materialize 工作副本；本需求不提前实现 Shape Key 拓扑迁移。

### R09 / P1：量化质量与视觉证据

返回目标缺口的剩余边界、连通片、重复/退化面、非流形、局部交叉和法线一致性。
形状检查使用参考曲面距离、固定边界位移和必要的接缝法线夹角，不只比较图片 SHA。
指标必须附检查区域与分母；局部修补不能默认要求原模型全局所有边界/交叉都为零。

自动验收可判断工程条件，艺术方向仍由用户决定；非零图像差异仅证明发生变化，不证明变好。

### R10 / P2：组合工作流与证据可视化

- 新写入沿用 `mesh.edit` 的封闭 operation 联合；检查入口优先复用现有资源/检查能力。
- 接入已有 batch 时保留 alias、自动 remap、预检零写入、运行期整事务回退和一次 generation 语义。
- 可选捕获证据标示四条边、角点、方向和问题位置，但不持久改变用户真实选择或创建场景辅助对象。
- 可先输出紧凑的建模步骤建议；建议不是自动执行许可，也不是一个任意脚本/单体自动补洞工具。

## 5. 共同约束与兼容

1. **用户意图优先**：明确建模请求授权对应常规事务链，不为每条边再询问。本文编写请求本身不授权执行这条链。
2. **UI 协作**：视图、Shading、Overlay、选择、活动对象变化不得误报硬冲突；模式、Scene、数据 identity/fingerprint 等仍按既有契约检查。
3. **保存接管**：原生保存接受当前可见状态，停止后续自动写入、回滚和重复保存；commit 本身仍仅保留内存。
4. **恢复**：单次写入失败先恢复本次调用；batch 运行期失败按已有整事务语义恢复。不得新建事务或刷新 guard 绕过真实用户修改。
5. **幂等**：每个逻辑请求一个 UUID，传输重试复用；no-op 不生成 delta/Map/generation。
6. **预算**：保持当前 1 MiB 请求、32 MiB 响应、30 秒期限、256 delta 及现有 Mesh/资源预算，不因补面自动放大。路径搜索与面生成须在写前检查最坏预算。
7. **兼容**：旧有效请求继续可用；新增字段/operation 独立 capability gate。字段名和 capability 版本由后续实施计划决定，不在本需求中假定已上线。
8. **工程边界**：增量 typed handler，不做大规模重构；不引入任意 Python/RNA/BMesh、全局自动修复、Undo 接管或角色专用 API。

## 6. 候选接口方向与未决选择

以下是设计候选，不是可立即调用的 MCP schema：

| 意图 | 优先候选 | 需要评审的选择 |
| --- | --- | --- |
| 检查边界与侧轨 | 扩展检查能力或独立 `mesh.boundary.inspect` | 分页响应还是短期预检 token；不默认新增资源簿 |
| 四边补片 | 扩展 `mesh.edit(grid_fill)` 的明确边界输入 | 四角/跨度与四条有序边的兼容；如何绑定路径证据 |
| 局部连接 | `mesh.edit` 中受控 edge/face creation | 初版一次单边/单面，还是复用 batch 执行多个 |
| 开链桥接 | 扩展既有 bridge operation | 分段不等时允许哪些显式重采样 |
| 塑形与验证 | 复用已有 SurfaceRef、deformation、validation | 任务级位移/距离阈值，不把一份角色尺度硬编码为全局范围 |

其他待决事项：

- 自动模式有多个有效网格方向时，选确定性默认并报告，还是要求调用方消歧？
- 隐藏边是否默认排除？明确路径是否可显式包含隐藏组件？无论选择哪项，都不得隐式改变真实隐藏状态。
- 新补片多 UV 层之间来自两侧不同图岛时，如何界定“可证明插值”与必须后续 unwrap？
- 无参考曲面区域的默认形状只能是几何插值，是否需要调用方明确接受后才进入交付验收？

这些选择影响工具结果与兼容性，应在实施计划中解决；不把调查假设写成已批准设计。
