# Blender MCP：角色缺失表面补全与可拆装模块需求

- Status: accepted product requirements and staged roadmap
- Evidence baseline: Blender Research MCP 0.14.0, audited 2026-09-01
- First implementation milestone: 0.15.0 materialize, extract, and rig binding

## 1. 文档目的

本文记录 `test-model.blend` 中角色网格的缺失表面与部件化问题，评估
Blender Research MCP 0.14.0 的现有能力，并提出一组通用、原子化、可组合的
MCP 能力需求。

本文讨论的是角色表面、衣物覆盖区、头部覆盖区、隐藏几何、拓扑边界和骨骼
绑定等建模工程问题。目标不是恢复厂商未公开的原始数据，而是生成结构合理、
可验证、可继续编辑的替代几何。

本文将现场审计证据、通用产品需求和建议工作流分开记录。审计数字是当时场景的
证据，不是协议常量；`test-model.blend` 只作为回归夹具，不进入本仓库。

## 2. 结论摘要

Blender Research MCP 0.14.0 已经具备补面所需的大部分几何内核能力，包括：

- 语义选区、边界和连通性查询；
- 填充、网格填充、桥接、切割和细分；
- 表面投射、松弛、平滑及定量验证；
- UV 和顶点组权重检查、迁移与验证；
- 拓扑版本、ComponentMap、事务和批处理；
- 单一连通区域的独立拆分。

但是，当前尚不能对 `test-model.blend` 中的源角色执行完整的端到端补全与模块化。
主要阻塞为：

1. 源网格带有大量形态键，所有拓扑写入被拒绝；
2. 缺少将当前基础或求值结果实体化为无形态键新网格的操作；
3. 材质区域由大量互不连通的小片组成，而现有拆分一次只接受一个连通区域；
4. 新建部件缺少完整的父子关系和骨骼变形绑定接口；
5. 衣物覆盖下的原始表面并不存在，必须由标准角色模板或受控形体笼推定，不能
   通过普通“封洞”自动恢复。

因此可以概括为：**几何补全面能力基本具备，但源网格解锁、非连通提取和装配绑定链
尚未闭合。** 0.15.0 优先闭合这条 P0 链；连通片目录、Collection 组织和跨对象批处理
进入 0.15.1，模板追加和覆盖面工作流进入 0.16。

## 3. 审计对象与现场证据

### 3.1 环境

- 审计日期：2026-09-01；
- Blender：4.2.23 LTS；
- Blender Research MCP add-on：0.14.0；
- 协议版本：1；
- 项目：`test-model.blend`；
- 场景：`Scene`；
- View Layer：`CODEX_V13_SUBJECT`；
- 目标对象：`绯雪_edit_mesh`；
- 审计方式：实时只读结构检查、SelectionSet 查询及正面/侧面/背面实体视图；
- 审计结束状态：无活动事务，Blender 项目未因审计变脏，用户视角与可见性保持。

### 3.2 源对象结构

`绯雪_edit_mesh` 不是“完整基础角色 + 独立衣物”的结构，而是把脸部、头发、
衣物、装饰和可见角色表面放在同一个 Mesh 对象中。

| 项目 | 现场值 |
| --- | ---: |
| 基础顶点 | 98,158 |
| 基础边 | 212,774 |
| 基础面 | 118,110 |
| 边界边 | 71,218 |
| 非边界型非流形边 | 0 |
| 材质槽 | 51 |
| UV 层 | 4 |
| 顶点组 | 761 |
| MCP 报告的可调形态键 | 137 |
| 变形修改器 | 1 个 Armature |

该网格仍处于 MCP 的规模预算内，但 `mesh.inspect` 明确报告：

```text

write_blockers: [MESH_SHAPE_KEYS_UNSUPPORTED]
writable_domains.geometry: false
writable_domains.uv: true
writable_domains.weights: true
```

即：当前仍可进行拓扑稳定的 UV 和权重写入，但不能改变顶点、边或面结构。

### 3.3 材质区域与开放边界

以下数字通过“材质面选区 → 转换为边选区 → 与全局边界边求交”获得：

| 语义区域 | 材质槽 | 面数 | 区域相关边 | 开放边界边 |
| --- | ---: | ---: | ---: | ---: |
| 脸部主表面 | 0 | 2,168 | 3,423 | 342 |
| 上部可见角色表面 | 26 | 10,632 | 17,438 | 2,980 |
| 下部可见角色表面 | 39 | 13,252 | 20,935 | 2,114 |
| 前后头发 | 12、14 | 20,694 | 38,341 | 14,600 |

这些开放边界包含不同含义：

- 有意保留的眼口等开口；
- 发片、衣物和装饰的正常外边缘；
- 材质壳之间本来就不焊接的接缝；
- 衣物或头发遮盖后被省略的角色表面；
- 需要进一步定位和分类的真实缺口。

因此不能把 71,218 条边界边全部当成错误并批量封闭。

### 3.4 连通片碎片化

抽取各材质区域中的第一个面作为种子，查询其完整连通片，得到：

| 区域 | 材质区域总面数 | 第一个连通片面数 |
| --- | ---: | ---: |
| 脸部主表面 | 2,168 | 1,884 |
| 上部可见角色表面 | 10,632 | 4,232 |
| 下部可见角色表面 | 13,252 | 512 |
| 头发 | 20,694 | 134 |

这证明“按材质拆分”并不等于“一件部件”。尤其是头发，同一语义区域由大量独立
发片和小壳组成。若现有 `mesh.separate` 坚持一次只接收一个连通区域，就需要大量
逐片操作，而且无法把结果重新组成一个逻辑对象。

## 4. 目标问题

### 4.1 缺失表面补全

希望角色在卸下头发或衣物模块后，不会暴露不存在的表面或大面积空洞。

补全结果至少应覆盖：

- 头发遮盖下的头部基础表面；
- 衣物遮盖下、换装时可能暴露的基础角色表面；
- 模块连接处必要的缓冲带和接缝区域；
- 由于原模型按固定造型优化而省略的其他隐藏表面。

补全的目标是形成视觉和结构合理的替代网格，而不是声称恢复唯一的厂商原始形状。

### 4.2 可拆装模块

希望最终结构至少可以独立控制：

- 完整基础角色；
- 头部覆盖补片；
- 前发和后发；
- 上装、下装、鞋和装饰件；
- 与不同衣物覆盖范围对应的基础表面区段。

“可拆装”不仅指静态隐藏和显示，还应包括：

- 独立对象或明确的对象组；
- 共享同一骨架并随姿态正确变化；
- 各自保留材料、UV 和必要权重；
- 重复装配不会产生重复对象、重复材质或重复修改器；
- 某个模块移除后，基础角色仍保持拓扑和视觉完整。

## 5. 非目标与事实边界

- 不要求从衣物轮廓唯一反演出不存在的原始表面；
- 不把所有开放边界都自动封闭；
- 不要求第一阶段迁移全部形态键到所有模块；
- 不要求通过任意 Python、任意 BMesh/RNA 或未约束 Blender Operator 绕过语义接口；
- 不把 `test-model.blend` 的物件名称硬编码为生产 API；它只应作为回归测试夹具；
- 不要求保留原对象不可修改。代理式流程是默认建议，但工具能力不应人为禁止
  经用户授权的直接修改。

## 6. 当前能力评估

### 6.1 已满足的基础能力

当前 0.14.0 已经适合在无形态键的普通 Mesh 上执行：

- 材质、空间、法线、尺寸和拓扑选区；
- SelectionSet 的并、交、差、扩张、收缩、边界和连通推导；
- fill、grid fill、bridge、subdivide、bisect 等拓扑编辑；
- 经过 ComponentMap 保护的多步拓扑链；
- 大区域的 smooth、relax、project、shrinkwrap 和 flatten；
- BASE 或 EVALUATED SurfaceRef；
- UV 与权重的保留、迁移、检查和批处理；
- 非流形、退化、方向、自相交、距离和穿透验证；
- 单一连通面区域的分离；
- 事务、自动回滚、幂等键和用户 UI 保留。

### 6.2 当前只能部分满足的事项

- 可以新建基础几何并拟合成独立补片，但复杂形体仍需要合适模板；
- 可以迁移权重，但不能完成新对象的骨架装配；
- 可以分离单一连通区域，但不能把多个连通片作为一个逻辑模块提取；
- 可以检查形态键对象的 UV 和权重，但不能修改其拓扑；
- 可以把现有对象当作求值表面，却不能将求值结果生成新的可编辑 Mesh。

## 7. 问题报告

### ISSUE-01：形态键网格缺少安全的拓扑工作副本

**级别：Blocker**

源对象具有形态键，复制对象仍会复制同一类拓扑约束。当前没有语义操作能够创建
“当前可见结果的静态、独立、无形态键 Mesh”。结果是新增的拓扑编辑能力无法作用
于本项目最重要的源网格。

### ISSUE-02：拆分只接受单一连通区域

**级别：Blocker**

实际生产部件经常由多个互不连接的小壳构成，例如发片、扣件、花纹和多层布片。
当前 `mesh.separate` 的单连通限制会把一个逻辑部件拆成大量对象，并且当前没有
语义化对象合并步骤完成回收。

### ISSUE-03：新部件缺少骨架装配接口

**级别：Blocker**

权重数据只是装配的一部分。新对象还需要：

- 与现有骨架建立精确关系；
- 创建或复制受控的 Armature 变形修改器；
- 按需设置父子关系；
- 验证顶点组名称与骨骼名称的匹配；
- 保证重复执行不会叠加修改器。

现有 Modifier authoring 不支持 Armature 类型，`object.set` 也不支持父子关系。

### ISSUE-04：缺少连通片枚举与语义分组证据

**级别：High**

现有 CONNECTED 查询需要种子，但不能一次返回：

- 连通片总数；
- 每个连通片的 SelectionSet；
- 面积、包围盒、材质集合与相邻关系；
- 小碎片与主体之间的可解释分类。

这使得大规模部件整理必须依赖索引试探或客户端循环。

### ISSUE-05：隐藏区域需要模板，而非普通封洞

**级别：Workflow Blocker**

头部覆盖区可以根据脸部、耳部和颈部附近的边界延拓；衣物覆盖区则缺少完整的目标
曲面。单纯 `fill` 会生成平盖，`grid fill` 只能在已有边界之间插值，都不能生成
稳定的完整角色轮廓。

需要可受控追加的标准角色模板或形体笼，再由 SurfaceRef 拟合和权重迁移完成适配。

### ISSUE-06：模块组织能力不足

**级别：Medium**

可拆装结构需要通用的 Collection 创建、对象链接/取消链接、父子关系和确定性命名。
当前只能把对象放入已经存在且已知身份的 Collection，难以由一次批处理创建完整的
模块层级。

## 8. 功能需求

### FR-01：`mesh.materialize`

提供一个受控操作，将一个基础或求值 Mesh 结果实体化为新的独立 Mesh 对象。

建议请求模型：

```json
{
  "source": {
    "object_name": "Source",
    "expected_object_identity": "object:...",
    "expected_mesh_identity": "mesh:...",
    "expected_mesh_revision_id": "..."
  },
  "evaluation": {
    "type": "SHAPE_KEYS_CURRENT",
    "expected_shape_key_state_fingerprint": "..."
  },
  "new_object_name": "Source_Materialized",
  "copy": {
    "materials": true,
    "uv": true,
    "weights": true
  },
  "collection": {
    "name": "Work",
    "expected_identity": "collection:..."
  }
}
```

最低语义要求：

- `evaluation` 必须显式选择：
  - `BASE`：基础 Mesh，不包含 Shape Key 值或 Modifier；
  - `SHAPE_KEYS_CURRENT`：烘焙当前 Shape Keys，并通过私有临时副本排除全部
    Modifier；这是需要重新绑定到 Armature 的默认工作流；
  - `FINAL_EVALUATED`：要求一个实时 EVALUATED SurfaceRef，烘焙当前帧、Shape
    Keys、Armature 和全部 Modifier；结果不得被默认解释为可重新绑定的静止体；
- 新对象必须拥有独立 Mesh 数据；
- 输出不带 Shape Keys、Modifier 或父级，保留源对象世界变换；
- 材质、UV 和权重复制策略必须逐域显式声明；请求保留但无法证明完整时整体失败；
- 返回源与新对象的精确身份、Mesh fingerprint、revision 和数据摘要；
- FINAL_EVALUATED 模式记录场景、View Layer、帧、变换、求值三角指纹和所用
  Modifier；
- 拓扑完全相同时返回 `MATERIALIZATION` ComponentMap；拓扑改变时不根据空间位置
  猜测 lineage；
- 不隐式删除、隐藏或替换源对象；
- 完整支持事务回滚、幂等和预算验证。

`BAKE_ALL_SHAPE_KEYS` 不属于第一阶段要求。若未来支持，应作为独立、复杂度更高的
能力设计，不能伪装成普通复制。

### FR-02：连通片目录

0.15.1 新增类似 `mesh.components.inspect` 的只读能力。它首先创建紧凑的
ComponentCatalog，而不是为每个碎片立即创建 SelectionSet：

```json
{
  "selection_id": "...",
  "domain": "FACE",
  "group_by": "CONNECTED",
  "include": ["COUNT", "AREA", "BOUNDS", "MATERIALS", "BOUNDARY_COUNT"],
  "offset": 0,
  "limit": 128
}
```

每个结果至少返回：

- 稳定的 session-local component identity；
- 紧凑的组件索引目录；只有调用方选中一个或多个 component identity 时才物化为
  一个 SelectionSet，避免超过现有 64 个 SelectionSet 的资源上限；
- 面数、面积、包围盒、边界数量和材质槽；
- 相对于原 SelectionSet 的覆盖率；
- 分页、截断和内容哈希。

### FR-03：`mesh.extract`

新增支持非连通面 SelectionSet 的提取操作。它不应替代现有、语义明确的
`mesh.separate`，而是作为另一种通用操作存在。

建议语义：

- 接受一个或多个连通片组成的 FACE SelectionSet；
- 将全部选中面提取为一个新对象；
- 源对象保留未选中面；
- 返回 SOURCE 和 EXTRACTED 两条 ComponentMap；
- 分别声明源和新对象的 UV/权重策略；
- 保留材质槽映射，并明确是否压缩未使用槽；
- 保留对象变换；
- 显式声明父级 `COPY/CLEAR_KEEP_WORLD`、Modifier `COPY/DROP` 和材质槽
  `PRESERVE_INDICES/COMPACT` 策略；
- 支持无写入的 preflight，报告选区是否为空、是否覆盖全部网格和预计规模；
- 事务失败时必须恢复对象、数据链接、材质、UV 和权重。

### FR-04：受控骨架装配

新增通用 `rig.inspect` 与 `rig.bind`。0.15.0 由 `rig.bind` 封闭处理 Armature Modifier
和可选父级；通用 `object.parent.set` 留给 0.15.1。

建议能力：

- 精确指定目标 Mesh 对象和骨架对象身份；
- 创建、替换或复用一个命名明确的 Armature 修改器；
- 指定是否设置对象父级；
- 绑定不隐式迁移、归一或修改权重；这些操作继续使用 `mesh.attribute.transfer` 和
  `mesh.weights.edit`；
- 检查顶点组与骨骼名称的匹配；
- 允许限定参与匹配的组集合，避免把所有辅助组误当成变形组；
- 报告未匹配组、未覆盖顶点、影响数和归一化结果；
- 通过精确的 existing-or-absent 证据创建或更新现有绑定，不产生重复修改器；
- 所有变更必须在结构事务中完成并可回滚。

### FR-05：通用对象与 Collection 组织（0.15.1）

需要补齐以下原子操作：

- `collection.create`；
- `collection.link_object`；
- `collection.unlink_object`；
- `object.parent.set` / `object.parent.clear`；
- 可选的 `object.join`，仅接受精确对象身份和明确的材质/UV/权重合并策略。

这些接口应保持通用 Blender 语义，不应出现“角色头发”“衣服”等特定领域名称。

### FR-06：受控模板追加（0.16）

若补全流程需要复用标准拓扑模板，建议提供只读检查加精确追加接口：

- `library.inspect(path)`：列出可追加的 Object、Collection 和 Mesh；
- `library.append(...)`：按绝对路径、数据块类型、名称和身份摘要追加；
- 默认不执行外部脚本；
- 不允许通配导入整个文件；
- 返回所有新数据块和依赖的精确身份；
- 支持事务回滚和名称冲突策略。

这不是任意资产导入器，而是带清单、身份和范围约束的 Blender 数据块追加能力。

### FR-07：批处理可组合性（0.15.1）

`mesh.batch.execute` 应能够引用：

- materialize 产生的新对象；
- components.inspect 产生的连通片 SelectionSet；
- extract 产生的 SOURCE/EXTRACTED 分支；
- UV 与权重迁移结果；
- rig.bind 和几何验证报告。

0.15.0 不以批处理作为 P0 前置条件：Agent 可以在同一事务中依次调用 materialize、
extract 和 bind。0.15.1 再提供更高层、仍然是声明式和封闭联合的跨对象批处理；不应
通过任意 Python 扩展批处理语言。

## 9. 建议实施流程

### 阶段 A：生成可编辑工作副本

1. 检查源对象、形态键、修改器、UV、权重与材质；
2. 以当前帧和当前形态值实体化 `SHAPE_KEYS_CURRENT` 网格，明确排除 Modifier；
3. 保留源对象作为动作、形态与视觉参考；
4. 验证新对象无形态键阻塞，材质、UV 和权重指纹符合复制策略。

### 阶段 B：建立语义模块

1. 按材质生成脸部、头发、衣物和可见角色表面选区；
2. 枚举并分类连通片；
3. 将属于同一逻辑模块的多个连通片一次提取为独立对象；
4. 为前发、后发、上装、下装、鞋和装饰建立独立模块；
5. 保留明确的源/提取 ComponentMap 和模块清单。

### 阶段 C：补全头部覆盖区

1. 识别脸部外缘、颈部连接区和需要保留的有意开口；
2. 从标准头部模板或低密度球面补片开始；
3. 将边缘投射到现有求值表面；
4. 使用 bridge/grid fill、smooth 和 relax 生成连续覆盖；
5. 保持补片略位于头发内部，避免外露和穿插；
6. 迁移头部相关权重并验证距离、方向、自相交和边界。

### 阶段 D：补全衣物覆盖区

1. 追加或使用项目内标准角色形体模板；
2. 以可见角色表面作为高置信目标；
3. 以衣物内表面和对称约束作为低置信参考；
4. 通过受控形体笼和表面拟合调整，而不是直接封洞；
5. 对衣物覆盖范围建立可切换的基础表面区段；
6. 验证不同模块组合下无明显空洞、重叠或接缝断裂。

### 阶段 E：绑定和装配

1. 将所有新部件绑定到同一骨架；
2. 迁移限定骨骼组的权重；
3. 限制每顶点影响数并重新归一化；
4. 创建确定性的 Collection 和父子层级；
5. 通过对象可见性完成装卸，不破坏拓扑；
6. 使用项目侧 manifest 记录模块、覆盖区和依赖关系。

## 11. 验收标准

### 11.1 工具级验收

- 所有写操作必须要求精确身份、revision/fingerprint 和 scene generation；
- 所有新操作支持事务回滚与幂等；
- 回滚后对象、Mesh、材质、UV、权重、修改器和父子关系均恢复；
- 用户视角、Overlay、选择和活动对象不因数据 API 操作改变；
- 不暴露任意 Python、任意 RNA/BMesh 或任意 Operator；
- 预检失败不得产生部分对象或脏数据块；
- 重复运行相同模块流程时，对象和修改器数量不增长。

### 11.2 场景级验收

- 原始 MMD 对象保持可回退；
- 完整基础角色在卸下模块后不存在非预期开口；
- 有意开口具有明确标签，不被自动封闭；
- 头部覆盖补片与脸部、颈部连接连续，无可见裂缝；
- 衣物覆盖区使用模板拟合结果，不出现大面积平盖；
- 每个模块可以独立隐藏和显示；
- 每个模块随同一骨架正确变化；
- UV、材料和限定变形权重得到保留或可解释迁移；
- 不存在明显退化面、错误方向、自相交或模块间严重穿插；
- 模块装卸不会改变源对象的形态键和原始绑定。

### 11.3 `test-model.blend` 回归夹具

至少增加以下端到端测试：

1. 将 `绯雪_edit_mesh` 当前求值结果实体化为无形态键副本；
2. 验证源对象的 Mesh fingerprint、形态键和绑定未变化；
3. 将包含多个连通片的头发材质选区提取为一个对象；
4. 验证提取后面数、材质、UV 和指定权重可追溯；
5. 将新对象绑定到 `绯雪_edit_arm`，重复执行不产生第二个 Armature 修改器；
6. 在事务中完成 materialize → extract → bind，然后完整回滚；
7. 模拟任一步骤失败，确认没有残留对象、Collection 或孤立 Mesh；
8. 连续运行两次完整流程，确认对象、数据块和修改器数量稳定。

## 12. 实施优先级

### P0：0.15.0 闭合最小端到端链

1. `mesh.materialize`；
2. 非连通 SelectionSet 的 `mesh.extract`；
3. `rig.inspect` 与 `rig.bind`；
4. 对应事务、回滚和回归测试。

### P1：0.15.1 提高自动化和可解释性

1. 连通片枚举；
2. Collection 创建与对象组织；
3. 批处理跨对象分支；
4. 模块级 manifest 与重复运行审计。

### P2：0.16 提高模板化建模质量

1. 受控 Blender Library 追加；
2. 标准拓扑模板与形体笼；
3. 更强的接缝、距离和模块组合验证；
4. 形态键迁移的独立研究方案。

Shape Key 结构写入和 Modifier Apply 不进入 0.15；两者需要独立的快照、映射和回归
设计，不能借 materialize 的“创建新输出”语义绕过。

## 13. 建议的第一项验证任务

在正式补全整个角色前，建议选择“头部覆盖补片”作为最小垂直切片：

1. 以 `SHAPE_KEYS_CURRENT` materialize 当前形态结果，排除 Armature 和其他 Modifier；
2. 提取脸部与头发模块；
3. 生成一个低密度、无形态键的头部覆盖补片；
4. 将边缘拟合到脸部和颈部附近；
5. 迁移限定的头部权重并绑定同一骨架；
6. 在隐藏头发后检查覆盖完整性；
7. 回滚并重复运行，验证确定性。

该任务规模较小，却能同时验证 materialize、非连通提取、表面拟合、权重迁移、
骨架装配、模块可见性和事务恢复，是最适合判断整条管线是否真正闭合的测试。

## 14. 最终建议

不要把本问题实现成 `complete_character_body`、`extract_hair` 等特定事物工具。
应当补齐通用 Blender 语义：

- 把求值结果变成可编辑 Mesh；
- 枚举和提取任意连通片集合；
- 将任意 Mesh 安全绑定到现有骨架；
- 组织对象和 Collection；
- 在一个封闭、声明式事务中组合上述操作。

一旦这些通用能力齐备，当前角色只是第一个回归夹具；同一套接口也可用于普通模型
清理、服装替换、机械组件拆分、扫描网格修复和其他模块化资产工作流。
