## 1. 结论与交付顺序

新增需求的共同目标是：保留已有角色结构，复用受控 NPR 材质，用固定相机判断效果，
输出原尺寸图片，再检查已有动作中的时序稳定性。完整网格重建、Shape Key 迁移和
骨架创作不是这条工作流的共同前置条件。

建议先修复现有验收工具的正确性，再补齐静态渲染闭环，然后引入长任务和已有动画采样。
保留已批准的 **0.18 Shape Key → 0.19 骨架创作 → 0.20 Modifier 最终化** 相对顺序；
生产级拓扑研究仍在 0.21 及以后另行立项。新渲染能力插入其前，具体发版边界待实施时冻结。

| 建议阶段 | 工作包及优先级 | 可交付结果 | 前置条件 |

A/B 是同一阶段的提交与验收顺序，不是两个隐含发布版本。若生产任务原型受设备或
缓存限制，0.17.7 可独立交付，0.18 可继续推进；不把 P2 研究变成全部模型编辑的无限期阻塞。
TMP-01 也不依赖材质模板或完整骨架编辑器。首版 TMP-02 复用 RND 是工程复用选择，
不表示 Blender 本身必须具备生产尺寸输出才能采样低分辨率帧。

## 3. 0.17.6：先恢复验收判定的可靠性

### QLT-01：候选与写后使用一致的实际三角化

1. 从报告提取三组面循环和坐标，制成可分发的最小合成回归，记录两种三角化的实际对角线、
   三角形对与接触分类。先判断是 tessellation、数值阈值还是接触判定差异，不预先锁死根因。
2. 在隔离临时 Mesh 上按最终面循环/坐标精度计算原生 loop triangles，复用局部接触内核。
   将顶点和面的对应显式保留；不能最近点匹配，也不能一概拒绝非平面四边形。
3. 在共同写入器 `write_bmesh_exact` 与属性恢复之后、Map/SelectionSet 发布之前，验证实际
   新面及邻接旧面。预检与写后不一致或检查不完整时，恢复本次调用；batch 仍恢复 begin 基线。
4. 验证期间预算不足也不能发布成功资源；错误包含阶段、面/三角形对、阈值、写回与恢复状态。
   保留旧坐标、UV/Pin/Seam、材质、权重及 Group identity 的现有恢复规则。

### QLT-02：TARGET_INTERSECTION 显式局部范围

为该检查增加可协商的 `scope=SELECTION/SELECTION_AND_NEIGHBORS`，复用 FACE/EDGE/VERTEX
到源面集合的现有转换。被选源面与整个目标 SurfaceRef 做相交，只返回规定源范围内的问题面；
邻接一圈必须返回实际分母。几何搜索可以读取目标全表面，但不等于允许报告任意源面。

无 scope 的旧请求先保留历史全对象行为，并明确返回 `effective_scope=OBJECT`；新客户端、
batch 验收和技能示例显式传 scope。这样避免静默改变旧请求，同时让局部验收可用。
若后续决定纠正默认范围，应另列兼容性变更，不在本补丁中顺带切换。
同时测试 SELF_INTERSECTION 现有显式 scope，避免把其旧无 scope 分支作为新局部验收路径。
相交命中不等于有符号穿透深度；开放毛发的 `sign_reliable=false` 继续如实报告。

### QLT-03：限值的数值误差与建模误差分离

保留“每顶点整次调用累计世界路程”的定义，不能退回净位移，也不能固定扩大 0.00001。
根据写入前后 float32 坐标、世界线性变换和迭代次数推导保守误差界，累计记录数值误差预算；
比较与返回证据包含请求限值、实测路程和误差界。法线与 falloff 的有效性需独立验证，
不能把非单位法线造成的真实放大一概算成舍入误差。
误差界大到无法区分用户指定限制时应明确拒绝，而非随场景坐标无限放宽。
必须覆盖零限值、零权重、正负 inflate、非均匀缩放、旋转、多步往返和真正超限。

## 5. 0.17.8：原尺寸输出与独立渲染作业

### RND-01–04 的首版取舍

首版建议只支持 Eevee、单机、有限并发；保留 `render.preview/save` 的旧同步接口与限制。
独立 Blender worker 是优先原型，复用外部 `lifecycle.py` 的托管资源与进程所有权机制，
由外部服务管理任务；add-on 只承担封闭的检查/渲染命令。不得把后台线程直接访问 bpy 当成异步方案。

原型首先回答：真实 3504×2016 渲染能否在预算内运行、主交互是否响应、任务是否可取消、
状态是否可在服务重启后恢复。未通过前不承诺长任务能力，不以放宽 RenderSize 冒充作业系统。

1. **冻结输入。** 首版接受明确的已保存 checkpoint 路径/SHA，建立任务自有不可变副本并核对
   材质、图像、Library、缓存等外部依赖指纹。需要当前未保存效果时，先由用户明确保存或
   另行授权快照导出；start 不自动保存活动场景。输出标明“来自该 checkpoint”，不冒充当前内存场景。
   外部依赖也应复制到任务目录并只重定向副本内引用，或提供可验证的不可变来源；
   只有开始/结束哈希不能证明中途没有读到混合数据，无法冻结的依赖在启动前明确拒绝。
   原源文件之后变化不污染 worker；原生保存接管只停止本工具对活动场景的恢复权。
2. **双重期限。** start/status/cancel/result 候选接口均保持原消息与 30 秒请求上限；
   job 自有执行时间、像素总量、采样、输出字节、磁盘与并发预算。设备可测的保守值在原型后冻结，
   明确哪些资源只能观测、哪些能硬性约束；交互超时不是取消。
3. **状态证据。** 记录输入/config digest、稳定 job ID、幂等 UUID、worker 所有权、阶段及终态。
   至少区分 QUEUED/RUNNING/CANCEL_REQUESTED/CANCELLED/SUCCEEDED/FAILED/UNKNOWN；
   无进度来源时返回未知，不能用等待时长伪造百分比。重启后先核对进程身份与产物，不自动重复渲染。
4. **取消与发布。** 优先协作取消，必要时只终止本任务拥有且身份核对过的 worker；
   取消完成须有进程终止和临时输出处理证据。取消与成功发布的竞态须有唯一终态，不能删除已经
   发布的成功文件。输出先写任务临时目录，验证尺寸/格式/字节/哈希后原子发布；覆盖许可与目标
   指纹在发布时复查，拒绝覆盖运行中被别人替换的文件。
5. **交付清单。** 全尺寸 PNG/EXR 文件与独立小预览分别标明尺寸、格式、哈希、耗时、引擎、
   相机、帧、输入与配置。不得把放大的 preview 当原尺寸渲染。临时资源清理和结果保留策略显式。

如果采用主进程原生作业替代 worker，必须先证明查询/取消可达、UI 响应、场景一致性及保存接管；
这是待决策项，不能在实现中静默切换输入/恢复语义。Cycles、农场、GPU 调度、视频编码与
Compositor 创作不在此阶段。

- **TMP-01**：以明确对象/骨架为根，只读遍历 Action、NLA、driver、constraint、Shape Keys、
  求值与缓存依赖，返回身份、范围、分页、预算和未覆盖项。区分源、当前帧物化代理与绑定目标；
  有 Armature/权重不等于动作完整。依赖检查可早于 RND 交付。
- **TMP-02**：对明确的小型 frame/subframe 清单，复用 RND checkpoint 与 worker，逐帧求值和
  捕获/渲染。首版不改 Action/关键帧/静止姿态，不自动迁移原模型动画到代理。保留请求顺序和实际
  求值顺序证据；总帧数、像素、时间/磁盘预算在原型中冻结，不能无界生成整个时间轴。
- **TMP-03**：把 frame/subframe 和求值配置加入时态资源键；切帧后重建 SurfaceRef，SelectionSet
  仅在对象、Mesh、拓扑及求值契约确有证明时复用，否则重建。即使整数帧相同而 subframe 不同，
  也不得复用旧表面。新帧资源不授权跨帧写入。worker 结束恢复其工具拥有的原时间/上下文，
  活动用户场景保持独立；非时间依赖漂移仍报告冲突。
- **TMP-04**：先实现无历史模拟的已有动作；同时检查历史依赖模拟。只有缓存身份、有效范围与
  所需资源均可验证时，才支持声明的缓存读取。无缓存或未知状态明确拒绝相关帧/标记未检查。
  顺序预热不是默认绕过，不做物理烘焙。任意驱动脚本、自动脚本执行、未知约束/求值处理器
  不能因为“已有动画”被自动放行；检查可报告，执行限定在验证过的支持范围。

逐帧返回姿态/表情、图像和可选几何指标，图像变化仅证明变化。相机下转头、转眼、眨眼及
颈部动作的视觉检查单列；有限采样不代表帧间插值、完整播放、物理或艺术验收全部通过。

每个阶段的实现提交前执行 `uv run --no-sync pytest`、`uv run --no-sync ruff check .`、
`uv run --no-sync mypy`，补齐 Python 3.11 AST、版本与安装包同步。原生变更需 Blender 4.2.23
连接/重连、上下文、rollback、UI 响应、原生保存接管及幂等门。作业还需实际设备压力与
进程异常门；接口可调用或产出一张图不构成该阶段完成。

真实角色笼拼接仍是单独未关闭项，本计划的补片/渲染验收不能代替。MAT/LDV 关闭首版
范围时保留可选多设置预设；TMP 标注实际支持的缓存/驱动范围，不能笼统关闭所有动画能力。

## 8. 增量落点、兼容性与实施前决策

| 工作包 | 优先修改/扩展的现有模块 | 增量模块与提交边界 |
| --- | --- | --- |
| QLT | `mesh_patch_quality.py`、`mesh_local_quality.py`、`mesh_surface_ops.py`、`mesh_topology_ops.py`、`mesh_deform_ops.py` | 三个独立修复提交，最后统一实机与文档验收；精确写回和事务结构保持 |
| LDV | 外部 `comparison.py`、`rendering.py`、`context_policy.py`；add-on `world_render_ops.py`、`context_ops.py`、`lookdev_ops.py` | 小型证据适配/配置清单与兼容规则模块；先单参数相机对照，再规则和故障恢复 |
| MAT | `library_assets.py`、`library_ops.py`、`lookdev_ops.py`、`material_authoring_ops.py`、现有 structural delta 恢复 | 封闭模板 schema、闭包检查与克隆模块；独立根→实例隔离→声明绑定→重载验收 |
| RND | `rendering.py`、`lifecycle.py`、服务注册与作业产物验证 | 外部作业状态存储、受控 worker runner；原型→状态与取消→文件发布→重连压力 |
| TMP | 上下文/资源模型、`mesh_surface_ops.py`、作业层 | 只读依赖摘要、时态资源验证、有限帧计划；检查先行，再无模拟采样与缓存用例 |

以上不授权大规模重构。公共 API 名和最终 schema 在各阶段的契约提交中冻结；计划优先
扩展既有 Library/compare/render 工作流。版本号、capability 和 transaction 能力均不在本轮改代码。

兼容性策略：

- 优先提升已有能力键，例如 mesh_validation/deformation、lookdev_inspection、material_authoring、
  library_inspection/append、render_preview/export；新增字段仅在能力存在时发送。
- `scope` 新语义、CAMERA_RENDER、MATERIAL 根、帧/子帧和作业操作必须做新旧客户端/add-on
  双向组合测试。独立 worker 还需匹配服务、runner 与 Blender 版本。
- 如需要新 capability 键，先设计客户端可识别的协商/过滤或明确的升级路径；不能向旧
  `extra="forbid"` 模型直接广播。protocol 1 可继续作为目标，不预先保证所有新作业/恢复
  语义都能保持 transactions 13；新 structural delta 权限必须在合同冻结时核算。

实施前需要通过小型原型定下的事项：材质可编辑闭包与图像隔离策略、独立 worker 的资源和
取消能力、checkpoint 外部依赖冻结、实际设备预算、支持的动画驱动/缓存集合。
默认建议已写在对应阶段；若原型迫使改变用户可见的输入、覆盖或保存语义，再进行范围决策。
现阶段没有缺失信息阻止文档更新；下一次实施从 QLT 三个最小回归开始。

本轮只提交本计划和相关文档索引/状态修正；原本未跟踪的 IDE 配置及缺陷报告保持原状。
GitHub issue 的发布、评论、关闭和程序实现均未在本轮执行。
