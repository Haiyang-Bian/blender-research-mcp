# Blender Research MCP 0.10.0 — bounded Modifier authoring

- Status: implemented; automated and Blender 4.2.23 live gates passed
- Target package and bundled add-on version: `0.10.0`
- Protocol: `1`
- Structural transaction capability: `3`
- Modifier authoring capability: `1`

## Purpose

0.10.0 adds a semantic non-destructive modeling layer without opening arbitrary RNA or
capturing destructive mesh topology. The supported domain is deliberately closed to
Bevel, Subdivision, Solidify, and Boolean on Mesh objects. Modifier apply and direct
vertex/edge/face or UV operations remain later milestones.

## Inspection and stack authority

`modifier.inspect(object_name)` returns the exact object identity, current generation,
the complete ordered stack up to 256 items, and a SHA-256 `stack_fingerprint`. Every
item includes its session identity, index, Blender type, support and pending-delete
state, viewport/render visibility, typed settings, writable fields/ranges, driver and
linked-data evidence, and exact Boolean operand identity when present.

Every write validates object and Modifier identity, type, index, complete stack
fingerprint, driver/read-only state, and final parameter constraints before mutation.
The transaction owns one evolving stack guard per object: each Agent mutation refreshes
the expected fingerprint, while commit, rollback, and disconnect recovery compare the
entire current stack. An external rename, add/remove, reorder, identity replacement, or
guarded-field change returns `MODIFIER_STACK_CONFLICT` and preserves user state.

## Typed writes

- `modifier.create` creates a uniquely named supported Modifier and optionally inserts
  it at an exact stack index.
- `modifier.set` applies a non-empty typed partial patch after validating the complete
  resulting state. A failure restores and verifies fields already changed by the call.
- `modifier.move` moves the exact identity to a legal index, including across an
  unsupported Modifier without modifying that item.
- `modifier.delete` disables viewport/render effect and marks the item pending. Commit
  removes it only after all guards pass; rollback restores the original identity,
  index, and state.

No-op requests create no delta and do not advance scene generation. A changed call
advances generation exactly once and returns before/after stack fingerprints, ordered
stack evidence, path-sorted changes, and its delta kind.

Bevel exposes bounded width, segments, limit/angle, affect, width mode, profile,
overlap, and normal controls. Subdivision exposes type, levels, render levels, quality,
control edges, limit surface, and creases with a two-million evaluated-base-face
budget. Solidify exposes thickness, offset, normal/rim controls, and enforces that rim
only implies rim. Boolean accepts one exact other Mesh object, rejects direct and
transitive cycles, limits combined base faces, and enforces solver-dependent options.

`modifier.set_state` retains its existing schema and remains available for the
viewport/render flags of any existing Modifier, including unsupported types.

## Comparison and compatibility

`lookdev.compare` adds `modifier_setting`. Its locator carries the complete inspected
object/Modifier identity, type, index, fingerprint, and exactly one comparable numeric,
integer, Boolean, or enum field. Each candidate independently executes begin,
`modifier.set`, capture, rollback, and complete-stack restoration verification.
Boolean operands, create, move, and delete are not comparison targets; comparison never
ranks, commits, applies, or saves.

A 0.10 server keeps the 0.9 surface when connected to a 0.9 add-on. Only the new
Modifier tools and `modifier_setting` require `modifier_authoring: 1`; missing
capability returns `CAPABILITY_MISMATCH` without widening global requirements.

## Acceptance

The automated suite covers schemas and ranges, exact inspection/fingerprints, all four
families, no-ops, idempotency, transaction capacity, atomic restoration, stack and
property conflicts, movement across unsupported entries, deferred deletion, Boolean
identity/cycle/solver constraints, performance budgets, comparison restoration,
capability compatibility, annotations, wheel/ZIP resources, and Python 3.11 syntax.

The live gate used an isolated port and temporary source-preserving `.blend` fixture.
It proved typed creation/configuration, ordering and rollback, independent stacks
on shared Mesh data, Boolean cycle rejection, visual comparison, injected user
conflicts, disconnect rollback, committed deletion, save/reload persistence, Eevee
evidence, heartbeat progress, and source SHA-256 preservation. Its evidence record is
recorded in
[the 0.10.0 validation record](../validation/2026-08-30-modifier-authoring.md).
