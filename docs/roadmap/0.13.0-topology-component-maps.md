# Blender Research MCP 0.13.0 — Topology revisions and ComponentMap

- Status: implementation in progress
- Target package and bundled add-on version: `0.13.0`
- Protocol: `1`
- Transaction capability: `7`
- Mesh topology capability: `2`

## Purpose

0.13 makes topology changes composable without treating post-operation indices as
stable identities. Every changed topology operation returns a bounded ComponentMap and
after-revision SelectionSets that can drive the next atomic write.

## ComponentMap contract

`mesh.component_map.inspect/release` and `mesh.selection.remap` manage one-step
revision lineage. Maps contain exact object/Mesh evidence, before/after revisions and
fingerprints, operation, content SHA-256, and paged per-domain relations. Forward
relations are `SURVIVED`, `SPLIT`, `MERGED`, or `DERIVED`; created and deleted indices
are separately inspectable.

Remapping supports all mapped descendants, exact survivors, or strict complete
coverage. Weighted selections copy one-to-many values and explicitly aggregate
many-to-one values. Maps never guess lineage from coordinates and never write
persistent IDs into the Mesh.

The resource book keeps at most eight maps, four million relations per map, and eight
million relations total. It uses compact integer arrays and LRU eviction. A map spans
one revision only; callers remap immediately after every topology write. Composition
belongs to 0.13.1.

## Bounded topology operations

The closed `mesh.edit` union adds SelectionSet-targeted subdivide, loop cut, bisect,
split, bridge, fill, and grid fill. Existing topology-changing operations also return
maps when used against a 0.13 add-on. New handlers reject invalid domains, branched or
ambiguous rings, incompatible boundaries, result-budget overflow, linked data, Edit
Mode, Shape Keys, and unsupported protected attributes.

Temporary BMesh lineage layers are removed before writeback. UV, color, material,
smooth, sharp, and supported attributes remain snapshot-protected and their
preservation/interpolation is reported. A failed write restores and verifies the
call-local snapshot before returning.

## Transaction and compatibility

Transaction capability 7 tracks map lifecycle. Commit keeps resources for the current
after-revision; rollback/disconnect restore the original Mesh revision and make the
after-state map stale. Native Blender save adopts the current topology as the user's
final visible state. User navigation, Shading, Overlay, selection, and active object
remain collaborative UI.

New capabilities are `mesh_component_map: 1` and `mesh_topology: 2`. A 0.13 server
continues to use 0.12 tools against an older add-on; only ComponentMap tools and the new
operation variants require transaction 7.

## Acceptance

Automated tests cover strict schemas, map pagination/budgets/LRU, weighted remapping,
all lineage classes, all seven operations, legacy topology operations, resource
lifecycle, shared Mesh scopes, attributes, compatibility, and packaging.

The Blender 4.2.23 gate uses a deterministic topology fixture plus a temporary copy of
`test-model.blend`. The character body remains a read-only evaluated Shape-Key target;
a separate proxy patch is subdivided, split, bridged, filled, surface-fitted, validated,
committed/rolled back, saved/reloaded, and rendered without changing the source file.

Object separation and declarative batches follow in 0.13.1. UV/weights remain 0.14;
Shape-Key writes and evaluated materialization remain 0.15.
