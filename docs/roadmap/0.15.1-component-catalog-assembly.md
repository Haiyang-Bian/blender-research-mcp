# 0.15.1 ComponentCatalog and cross-object assembly roadmap

- Release: `0.15.1`
- Protocol: `1`
- Blender target: `4.2.23 LTS`
- Python syntax target: `3.11`
- Transaction capability: `11`
- Status: implemented; release validation recorded separately

## Purpose

0.15.1 makes the 0.15 modular Mesh pipeline explainable and composable without adding
character-specific tools:

```text
FACE SelectionSet -> ComponentCatalog -> selected components
    -> materialize/extract -> Collection/parent organization -> rig.bind
```

The release adds compact connected-component evidence, exact scene organization, and a
cross-object extension of the existing declarative Mesh batch. It does not persist a
module registry in the blend file.

## Public surface

- `mesh.component_catalog.prepare/inspect/select/release` creates a bounded,
  revision-bound directory and materializes SelectionSets only for chosen components.
- `collection.inspect/create/link_object/unlink_object` reports and edits exact
  Collection structure without Blender name suffixing.
- `object.parent.set/clear` applies exact OBJECT parenting or clears an inspected
  existing parent with explicit world/local transform semantics.
- `mesh.batch.execute` v3 adds ComponentCatalog, materialize, extract, Collection,
  parenting, and rig-binding aliases while retaining every v1/v2 request.

Catalogs retain at most 16 resources, 2,000,000 face references, and 500,000 connected
components. One selection request names at most 4,096 component identities. Batch
limits remain 8 initial Mesh targets, 32 steps, 64 aliases, 256 transaction deltas, a
1 MiB request, a 32 MiB response, and a 30 second command deadline.

## Transaction and compatibility boundary

New Collection and parent deltas validate the Agent's last written structure before
rollback. Catalog validity follows the actual Mesh revision: baseline catalogs become
valid again after a proven rollback, while catalogs created for an abandoned
after-revision become stale. Native save accepts the visible scene and terminates later
writes as in transaction-v10.

Capabilities are `mesh_component_catalog: 1`, `collection_authoring: 1`,
`object_parenting: 1`, `mesh_batch: 3`, and `transactions: 11`. A 0.15.1 server keeps
all old tools usable against a 0.15 add-on and rejects only the new surface.

## Acceptance

Automated tests cover catalog partitioning/resources, Collection and parent deltas,
cross-object aliases, whole-transaction recovery, native save, compatibility, schemas,
and package resources. The Blender 4.2.23 gate uses a deterministic multi-shell fixture
and a temporary `test-model.blend` copy. It must discover the real character's hair
components semantically, assemble an extracted module, prove idempotent replay, and
leave the source file hash unchanged.

## Deferred work

0.15.1 does not add `object.join`, Collection deletion, Bone Parent creation, Library
append, templates, persistent custom-property manifests, Shape-Key structure writes,
Modifier Apply, arbitrary BMesh/RNA/Python, or retopology. Bounded Library append and
template-based coverage remain the 0.16 direction.
