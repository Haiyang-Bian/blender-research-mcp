# 0.17.0 cross-object Mesh composition roadmap

- Release: `0.17.0`
- Protocol: `1`
- Blender target: `4.2.23 LTS`
- Python syntax target: `3.11`
- Planned transaction capability: `13`
- Status: accepted plan; implementation not started

## Summary

0.17 closes the structural gap between object-level modular assembly and one
continuous editable Mesh:

```text
exact Mesh objects -> preflight schemas and coordinate frames -> independent join
    -> per-source JOIN_BRANCH maps -> inspect mapped boundaries -> explicit weld
    -> UV/weight/topology validation -> optional guarded source deletion
```

The release adds no character-specific command. It composes general Mesh objects and
keeps join separate from weld so spatial proximity is never treated as automatic
semantic permission to merge a seam.

Before implementation, merge the validated 0.16 branch through a merge-commit PR,
update local `main`, and create `codex/cross-object-mesh-composition`. Do not push,
merge, or clean the new 0.17 branch after its local release gate.

## Public interface

### Join preflight

```text
mesh.join.preflight(
    sources,
    output,
    attributes,
    dependencies
)
```

`sources` contains 2–32 exact Mesh-object records. Each record carries:

- object name and session identity;
- Mesh name, identity, users, complete user-object set, fingerprint, and revision;
- object transform/structure fingerprint;
- material-slot, UV, Vertex Group, weight, color-attribute, Shape-Key, and Modifier
  summaries needed by the selected policy.

`output` is a closed record:

- exact unique `new_object_name` and `new_mesh_name`;
- exact destination Collection identity and structure fingerprint;
- `coordinate_frame: WORLD | SOURCE_OBJECT`;
- when using `SOURCE_OBJECT`, the exact source object which supplies the output world
  matrix;
- `source_disposition: KEEP | DELETE_ON_COMMIT`.

`attributes` explicitly selects:

- materials: `PRESERVE_BY_IDENTITY | ERROR_IF_DIFFERENT | DROP`;
- UV Layers: `MERGE_BY_NAME | ERROR_IF_SCHEMA_DIFF | DROP`;
- Vertex Groups/weights: `MERGE_BY_NAME | ERROR_IF_SCHEMA_DIFF | DROP`;
- color attributes: `MERGE_BY_NAME | ERROR_IF_PRESENT | DROP`;
- generic attributes: `ERROR_IF_PRESENT | DROP`;
- custom split normals: `ERROR_IF_PRESENT | DROP_RECALCULATE`.

`dependencies` states how source-only structure is handled:

- Shape Keys: `ERROR_IF_PRESENT | DROP_OUTPUT`;
- Modifiers: `ERROR_IF_PRESENT | DROP_OUTPUT`.

Join always reads each source's BASE Mesh. When evaluated geometry is intended, the
caller must first use `mesh.materialize`; join never silently bakes a source Modifier,
Shape Key, Armature, or frame-dependent result. `DELETE_ON_COMMIT` with a drop policy
is an explicit request to discard those source-only dependencies.

Preflight returns transformed geometry budgets, output counts, the deterministic
material/UV/group schema, every source-to-output mapping, warnings, and the number of
transaction deltas required. It is read-only and does not create session resources.

### Transactional join

```text
mesh.join(
    transaction_id,
    sources,
    output,
    attributes,
    dependencies,
    expected_scene_generation,
    idempotency_key
)
```

The mutation repeats the complete preflight against live evidence, then creates one
independent output object and Mesh through Blender data/BMesh APIs without relying on
mode, selection, active object, or an operator. All vertices are transformed into the
chosen output-local frame before one write.

The result includes:

- exact output object/Mesh evidence, revision, fingerprints, and counts;
- deterministic material-slot, UV-Layer, color-attribute and Vertex Group mappings;
- one `JOIN_BRANCH` ComponentMap for every source, all sharing one `join_id`;
- rebound output SelectionSets for any declared source input selections;
- per-source VERTEX/EDGE/FACE SelectionSets on the output revision;
- boundary selections suitable for subsequent weld and validation;
- preserved, dropped, recalculated, and unsupported dependency evidence;
- source disposition and transaction delta summary.

A JOIN_BRANCH is intentionally a partial output lineage view: it records only the
components descended from that exact source. Components contributed by other sources
are not mislabeled as CREATED. Existing inspect/release/remap tools gain this map kind.

`DELETE_ON_COMMIT` reuses guarded deferred object deletion after the output has been
created. Sources disappear from the visible assembly during the transaction, rollback
relinks the same objects, and commit removes them only after every source/output guard
passes. `KEEP` leaves every source untouched.

Annotation:

```text
readOnly=false / destructive=true / idempotent=true / openWorld=false
```

### Explicit seam welding

Extend the existing `mesh.edit` operation union:

```text
{
  type: "weld_vertices",
  selection_ids,
  mode: "ALL_SELECTED" | "CROSS_SELECTIONS",
  maximum_distance,
  destination: "LOWEST_INDEX" | "CENTER",
  weight_merge: "MAX" | "AVERAGE" | "SUM_NORMALIZE"
}
```

- Accept 1–8 VERTEX SelectionSets from the same live Mesh revision.
- `CROSS_SELECTIONS` requires disjoint sets and only forms groups containing vertices
  from different sets; it is the default for joining seams.
- `ALL_SELECTED` may weld within one union selection.
- Candidate groups use a deterministic spatial index, then stable lowest-index tie
  breaking. No coordinate-nearest guess is recorded as lineage until the request's
  explicit distance rule accepts the pair.
- `maximum_distance` is finite, positive, and bounded by the existing Mesh coordinate
  range. At most 65,536 selected vertices and 65,536 accepted pair relations may be
  processed in one call.
- UV remains loop-owned. Material and face state remain unchanged. Vertex weights use
  the requested merge rule; unsupported point attributes follow the topology attribute
  policy.
- No accepted pair is a no-op: no delta, ComponentMap, or generation change is created.
- A changed result returns exact MERGED vertex lineage, rebound SelectionSets,
  boundary counts, attribute effects, and the new Mesh revision.

## Transaction and resource model

- Add `MeshJoinDelta` plus one guarded output-closure record.
- Every source object, source Mesh, Collection, material, image, UV schema, Group
  schema, and chosen coordinate-frame object is validated before creation.
- The new output joins the existing Mesh snapshot/resource lifecycle so later weld,
  deformation, UV, weight, bind, parent, or Collection writes refresh its guards.
- Call-local failure removes the incomplete output and proves every source state before
  returning. Failure to prove recovery returns `MESH_JOIN_RESTORE_FAILED`.
- Rollback/disconnect removes an unchanged Agent-owned output and restores any deferred
  source deletions. User-modified output or source state returns
  `MESH_JOIN_DATA_CONFLICT` and is not overwritten.
- Commit preserves the output and finalizes source deletion only after complete guard
  validation.
- Native Blender save accepts the currently visible joined/welded state and prevents
  later automatic rollback.
- Successful join advances scene generation once. Join plus weld inside batch v5 also
  advances global generation once while retaining per-step Mesh revisions.

ComponentMap resources rise to version 4. A source JOIN_BRANCH may compose with later
single-output weld/topology maps. Composition remains exact lineage arithmetic; maps
from unrelated joins or stale output revisions are rejected.

## Batch v5

Extend `mesh.batch.execute` without changing v1–v4 schemas:

- add `mesh_join` consuming 2–32 target aliases and registering one output target;
- allow `mesh_edit(weld_vertices)` to consume the join's source/boundary SelectionSet
  aliases;
- register every JOIN_BRANCH map and automatically compose each source path through
  later output topology revisions;
- mark source aliases as retained or terminal according to source disposition;
- expose attribute schema maps and boundary validation in `assembly_manifest`;
- preflight all names, references, coordinate frames, schemas, geometry budgets,
  response budgets, and transaction capacity before the first write.

Any runtime write, resource, assertion, or map-composition failure restores the entire
active transaction, including writes made before the batch. One idempotency UUID
covers the complete batch.

## Capabilities and compatibility

Planned capability versions:

- `mesh_join: 1`
- `mesh_topology: 5`
- `mesh_component_map: 4`
- `mesh_batch: 5`
- `transactions: 13`

A 0.17 server connected to a 0.16 add-on retains every existing tool and batch-v4
step. Only join, weld, JOIN_BRANCH resources, and batch-v5 composition return
`CAPABILITY_MISMATCH`.

- `MESH_JOIN_SOURCE_INVALID`
- `MESH_JOIN_SOURCE_DUPLICATE`

## Automated tests

Cover:

- all strict schemas, extra fields, finite values, duplicate sources, exact names, and
  coordinate-frame transforms;
- preflight zero-write guarantees and deterministic schema maps;
- identity/name-deduplicated material slots, same/different UV schemas, weight Groups,
  zero weights, locked Groups, color layers, generic attributes, and custom normals;
- Shape-Key and Modifier dependency policies, including explicit drop behavior;
- output geometry counts and one exact JOIN_BRANCH map per source;
- KEEP and DELETE_ON_COMMIT, commit, rollback, disconnect, native save, conflict, and
  idempotent replay;
- weld pair grouping, cross-selection restriction, tie breaking, no-op, weight merge,
  topology lineage, budgets, and complete restoration;
- JOIN_BRANCH inspect/remap/compose and stale resource lifecycle;
- batch-v5 aliases, automatic per-source composition, one-generation success,
  preflight failure, runtime whole-transaction recovery, and response manifest SHA;
- collaborative viewport/selection behavior, 1 MiB request, 32 MiB response, and
  30-second deadline;
- 0.16 compatibility, Python 3.11 AST, skill source, managed bootstrap, wheel, and ZIP.

## Blender 4.2.23 acceptance

Use an isolated port and `%TEMP%` files:

1. Generate two or more deterministic open Mesh modules with complementary boundary
   rings, non-identity transforms, materials, UVs, colors, Vertex Groups, and weights.
2. Prove preflight changes no data count, generation, mode, selection, or viewport.
3. Join in WORLD and SOURCE_OBJECT frames; verify exact output coordinates and every
   per-source map.
4. Inspect the unjoined shells, then weld only the mapped boundary selections. Require
   one connected component, the expected vertex-count reduction, zero seam boundary
   edges, no degenerate faces, and preserved UV/weight evidence.
5. Cover KEEP and DELETE_ON_COMMIT through rollback, forced disconnect, commit, native
   save, save/reload, and idempotent replay.
6. Inject source, output, material-user, Collection, and boundary coordinate conflicts;
   preserve the user's values and return the stable conflict.
7. Run one batch v5 from temporary Library append through alignment, surface fitting,
   join, weld, weight transfer, rig binding, validation, and Collection organization.
8. In a `%TEMP%` copy of `test-model.blend`, keep `绯雪_edit_mesh` as read-only
   EVALUATED evidence; append deterministic head/body cage modules, fit visible
   anchors, retain hidden priors, join and weld a neck seam, transfer bounded weights,
   and bind to `绯雪_edit_arm`.
9. Require no new non-manifold, degenerate, or self-intersection defects; record seam
   boundary count, distance percentiles, unsigned/signed penetration reliability, UV
   and weight validation, and multiple nonzero-difference captures.
10. Confirm the source character and Library SHA-256 values remain unchanged.
