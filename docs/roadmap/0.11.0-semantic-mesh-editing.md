# Blender Research MCP 0.11.0 — semantic Mesh editing

- Status: implemented; automated gates passed; Blender 4.2.23 release gate pending
- Target package and bundled add-on version: `0.11.0`
- Protocol: `1`
- Transaction capability: `4`
- Mesh topology capability: `1`

## Purpose

0.11.0 adds bounded component-level modeling without exposing arbitrary BMesh, RNA, or
Python. The new surface operates on the base Mesh data-block. Modifier-evaluated
geometry remains a separate read-only concern of `object.geometry.inspect`.

Use a material for visual surface detail such as water ripples, a supported Modifier
for a non-destructive whole-object effect, and `mesh.edit` only when the requested
result needs real silhouette, structure, or component changes. UV authority remains a
separate 0.12 milestone.

## Exact inspection and index authority

`mesh.inspect(object_name, component, offset, limit)` returns the object and Mesh
session identities, complete object-user set, base counts and budgets, material slots,
UV/color/generic-attribute evidence, and two SHA-256 fingerprints:

- `topology_fingerprint` covers ordered connectivity with canonical undirected edges;
- `mesh_fingerprint` additionally covers coordinates, selection/hide state, edge
  sharpness, face material/smooth state, material-slot identities, and supported
  protected attributes.

Vertex, edge, and face pages include exact current indices and semantic measurements.
An index is valid only with the full `mesh_fingerprint` that accompanied it. Any
successful topology mutation invalidates old indices; callers must inspect again.
`object.geometry.inspect` continues to report evaluated geometry and does not grant
base-component write authority.

## Unified bounded edits

`mesh.edit` accepts exactly one closed operation:

- transform exact vertex/edge/face selections around a median or explicit local pivot;
- region-extrude or region/individual-inset exact faces;
- bevel exact edges;
- delete or dissolve exact component selections with fixed semantic propagation;
- merge exact vertices to their center or one selected target;
- set exact face material slot and/or smooth state;
- flip exact faces or recalculate the complete Mesh consistently outward.

The server and add-on both validate closed fields, strict JSON types, finite ranges,
unique indices, target cardinality, mode, fingerprints, user scope, transaction
capacity, and result budgets before one BMesh writeback. A changed call advances scene
generation once and records one Mesh delta. A no-op removes a newly created snapshot,
records no delta, and does not advance generation. Responses identify before/after
Mesh data, fingerprints, counts, requested components, and bounded created/deleted
indices.

## Shared data and reversible snapshots

Every write explicitly selects a data scope:

- `OBJECT` edits only the target object. If its Mesh is shared, the transaction creates
  a single-user copy, and rollback restores the original data link and removes the
  copy.
- `SHARED_DATA` edits the existing data-block for every exact inspected object user.
  The full user-name/identity set and Blender user count must still match.

The first edit of one working Mesh in a transaction saves one complete `Mesh.copy()`
baseline. Later edits reuse that snapshot and advance the guard's expected fingerprint.
Commit validates identity, users, protected data, and fingerprint before discarding the
snapshot. Rollback and disconnect recovery validate the same evidence before restoring
the baseline into the same Mesh identity. User coordinate, topology, attribute,
material-slot, or sharing changes return `MESH_DATA_CONFLICT` and remain untouched.

Each call also owns a temporary pre-write snapshot. If a Blender/BMesh failure occurs
after partial writeback, the call restores and verifies its immediate previous state.
Failure to prove that restoration returns `MESH_EDIT_RESTORE_FAILED` and stops the
workflow.

## Bounds and rejected data

The base/result limits are 500,000 vertices, 1,000,000 edges, 500,000 faces, and
2,000,000 loops. One request targets at most 4,096 components, and response index lists
are bounded with explicit truncation evidence. Library-linked Meshes, edit-mode data,
pending-delete objects, Shape Keys, unsupported generic attributes, and non-object Mesh
users are rejected before mutation.

UV and color layers plus supported generic attributes participate in fingerprints,
snapshots, BMesh propagation, and rollback, but this version cannot edit their values.
There is no arbitrary coordinate-array replacement, Knife, Loop Cut, Bridge, Modifier
Apply, Shape-Key topology, Geometry Nodes, generic RNA, or arbitrary Python surface.

## Compatibility and acceptance

A 0.11 server preserves all 0.10 tools against an older add-on. Only `mesh.inspect` and
`mesh.edit` require `mesh_topology: 1`, and edits additionally require
`transactions: 4`. Capability mismatch does not widen the global handshake or remove
older object/material/Modifier workflows.

The automated gate covers schemas, capability/annotation snapshots, strict operation
constraints, transaction guards, packaging resources, and Python 3.11 syntax. The
release gate will use Blender 4.2.23 on an isolated port and temporary source-preserving
fixture to prove all nine operation families, both sharing scopes, commit/rollback,
conflict preservation, disconnect recovery, save/reload persistence, Eevee evidence,
heartbeat progress, and source SHA-256 preservation.
