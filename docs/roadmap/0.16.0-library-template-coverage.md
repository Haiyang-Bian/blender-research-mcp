# 0.16.0 controlled Library and template coverage roadmap

- Release: `0.16.0`
- Protocol: `1`
- Blender target: `4.2.23 LTS`
- Python syntax target: `3.11`
- Transaction capability: `12`
- Status: implementation in progress

## Purpose

0.16 closes the remaining asset-ingress gap in the modular character workflow:

```text
exact local .blend -> inspect SHA-bound entries -> transactional append
    -> align template -> select visible anchors -> fit evaluated surface
    -> preserve hidden cage prior -> transfer weights -> rig.bind -> validate
```

The release supplies general Library and batch primitives. It does not add a
character-specific fitting command or claim to recover geometry hidden by clothes or
hair.

## Public surface

- `library.inspect` lists exact Object, Collection, and Mesh roots from one absolute
  local `.blend` file and binds them to the file SHA-256.
- `library.append` appends one inspected root as local data with an explicit output
  name and destination, then records its bounded dependency closure in transaction
  v12.
- `mesh.batch.execute` v4 binds exact Library sources and adds `library_append`,
  `object_set`, and `mesh_surface_prepare` steps so imported objects can enter the
  existing selection, fitting, transfer, organization, rig, and validation pipeline.

Source files are not directory-restricted. Root names never silently gain `.001`.
Imports are local copies rather than Library Links or Overrides. Scripted and
unsupported dependency graphs are rejected before the result is accepted.

## Transaction and compatibility boundary

Library append records the root plus every new dependency, their names, identities,
users, and supported structure fingerprints. A normal rollback or disconnect deletes
the closure only when it still matches the last Agent-authored state. User changes
produce a conflict and remain untouched. Native Blender save continues to accept the
currently visible result and terminates later Agent writes.

A successful batch advances scene generation once. A runtime failure restores the
entire active transaction, including writes made before the batch. Library evidence,
dynamic SurfaceRefs, object transforms, Mesh revisions, weights, binding, and
validation appear in the response-only assembly manifest.

Capabilities are `library_inspection: 1`, `library_append: 1`, `mesh_batch: 4`, and
`transactions: 12`. A 0.16 server preserves old tools against a 0.15.1 add-on.

## Acceptance

Automated tests cover catalog evidence, exact names, all three root kinds, bounded
dependency closure, unsupported scripted data, transaction recovery, idempotency,
batch aliases, dynamic SurfaceRefs, compatibility, and release resources.

Blender 4.2.23 validation creates a deterministic temporary Library containing a head
cage, segmented body cage, UVs, weights, materials, a static Armature, and nested
Collections. It proves read-only inspection, Object/Collection/Mesh append, recovery,
save/reload, and a complete batch-v4 fitting flow. A temporary `test-model.blend`
copy then fits visible anchors while retaining hidden template regions, transfers
bounded weights, binds to the inspected Armature, validates seams/intersections, and
leaves the source file SHA-256 unchanged.

## Deferred work

0.16 does not add network asset download, Library Link/Override, arbitrary scripts or
drivers, role-specific fitting tools, persistent manifests, Shape-Key structure
writes, Modifier Apply, arbitrary BMesh/RNA/Python, or retopology.
