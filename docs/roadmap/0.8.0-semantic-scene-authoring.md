# Blender Research MCP 0.8.0 — semantic scene authoring

- Status: implemented; automated gate and Blender 4.2.23 acceptance passed
- Target package and bundled add-on version: `0.8.0`
- Protocol: `1`
- Structural transaction capability: `3`

## Purpose

0.8.0 closes the loop from an empty or existing project to an inspected, authored,
reviewed, rendered, and optionally saved static Blender scene. The release adds useful
write authority without exposing arbitrary Python, generic RNA, mesh-component editing,
or arbitrary shader nodes.

A direct user request to build or modify a scene authorizes one coherent in-memory
transaction. The Agent discovers exact resources, performs the bounded writes, reviews a
preview, and commits when verification succeeds. A conflict or failed preview rolls the
entire batch back. Commit still does not save the `.blend`; project and render exports
remain explicit lifecycle/deliverable operations.

## Tool surface

Discovery:

- `scene.inspect(kinds, name_filter, limit)`
- `image.inspect(image_name)`
- extended `material.inspect` node, link, image-node, and Principled-channel evidence

Structural writes:

- `object.create`, `object.duplicate`, expanded `object.transform`, and `object.delete`
- `material.create`, `material.assign`, `image.load`
- `material.texture.bind` and `material.texture.clear`
- `world.set` and `scene.camera.set`

Reviewed output:

- `render.preview` returns a validated Eevee Next PNG plus hash and settings evidence.
- `render.save` overwrites one explicit absolute PNG or EXR and returns its file hash.

Every structural writer requires an active transaction, the current generation, one
logical idempotency UUID, and all relevant exact session identities. New tools require
their individual 0.8 capability, while a 0.8 server retains the 0.7 baseline handshake
and can use older tools against a 0.7 add-on.

## Structural transaction v3

Transactions now combine typed property deltas and Blender-private structural deltas,
bounded to 256 total entries. Structural guards record resource identity, users, and a
fingerprint covering supported topology, slots, nodes, links, images, World assignment,
and active Camera state.

Creation rollback removes only the still-matching transaction-created resource and its
exclusive owned data. Object deletion unlinks first, relinks on rollback, and removes
the object data-block only after all commit guards pass. Existing deleted-object data is
left orphaned; data created and then deleted inside one transaction is cleaned when its
users reach zero. Material slots and exact node links restore in reverse order. A user
identity, context, property, structure, link, or user-count change yields a conflict and
is never force-overwritten.

## Bounded authoring model

Object creation is limited to plane/grid/cube, UV sphere, ico sphere, cylinder, cone,
Empty, Camera, and point/sun/spot/area lights. Transforms are absolute Blender units,
XYZ Euler degrees, and local scale. Names are exact and unique; non-root collections
require inspected identities.

Materials use one canonical Principled BSDF and Material Output. Exposed values are base
color, metallic, roughness, IOR, transmission, emission, and alpha. Texture binding is
limited to base color, roughness, metallic, normal, bump, emission, and alpha through
fixed Texture Coordinate, Mapping, Image Texture, and optional Normal Map/Bump helpers.
Replacing a link requires the complete inspected link-identity set.

Images come only from arbitrary absolute local paths. 0.8 supports load/reuse and
AUTO/SRGB/NON_COLOR policy, but not downloads, pack/unpack, or reload. World authoring
supports background color/strength plus a local environment image and Z rotation.

## Render contract

Both render tools use Blender 4.2 Eevee Next, exact Camera identity, dimensions from 256
through 1000, and 1–64 render samples. They restore the previous active Camera, engine,
resolution, transparency, output path/format, and Eevee sample count. Preview renders a
temporary PNG, reloads it in Blender to verify dimensions and grayscale variation, then
removes it; the external process verifies PNG bytes, SHA-256, and response size before
returning MCP image content.

`render.save` accepts only an absolute `.png` or `.exr` path with an existing parent,
validates a same-directory temporary render and atomically overwrites the target, then
returns the bytes and hash actually written. Cycles, animation,
batch frames, compositor control, and render-farm execution remain out of scope.

## Acceptance

The automated suite covers closed schemas, annotations, capability defaults, structural
guards/delta limits, object and material value validation, render PNG validation, add-on
Python 3.11 syntax, packaging, and the 0.7 compatibility baseline.

The real Blender gate uses temporary files only. A deterministic fixture exercises
create/rollback/commit/conflict/disconnect behavior and persistence after reload. The
moonlit-water scenario builds a water grid, moon sphere, two Cameras, lights, the
`#EFF0EA`, `#C9DEE5`, and `#214268` palette, deterministic wave/star images, two distinct
preview views, PNG exports, an EXR export, commit, save, reload, re-inspection, and a
second render. Source fixtures are protected by before/after SHA-256.

This gate passed on 2026-08-29. The exact run, hashes, conflict/disconnect evidence,
render metrics, and visual review are recorded in
[`docs/validation/2026-08-29-semantic-scene-authoring.md`](../validation/2026-08-29-semantic-scene-authoring.md).

Independent 0.6 comparative-preview acceptance remains pending and is reported
separately from this authoring gate.
